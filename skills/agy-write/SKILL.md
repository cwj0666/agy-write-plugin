# agy-write

## 기본 원칙

- Claude는 파일 내부의 글을 직접 작성하거나 수정하지 않습니다. 대화창의 응답 문장은 평소대로 작성합니다.
- 범용 절차를 정의하며 특정 프로젝트 규칙은 두지 않습니다. 프로젝트별 규칙은 해당 저장소 문서(AGENTS.md 등)에 정의하고 작업 시 요청(REQUEST) 인자로 전달합니다.
- 글 작성 규칙(코드 옆 주석은 명사형, docstring과 JSDoc 설명과 파일 머리 설명은 ~합니다 문장)은 `assets/annotate-prompt.md`에 정의합니다. 세부 조건은 해당 기준을 따릅니다.
- Claude는 JSON 재료를 조립하지 않고 파일 경로, 작업 위치, 추가 요청만 전달합니다.
- 요청(REQUEST)에는 사용자 요청이나 코드에 없는 정보(결정 이유 등)만 기재합니다. 문장, 용어, 구성은 직접 지정하지 않습니다.
- 문서 작성 요청인 경우 사용자 요청 내용을 요청(REQUEST) 값으로 전달합니다.
- 요청(REQUEST) 작성 기준:
  - 값을 바꾸는 사실은 기본값, 새 값, 방향을 함께 적습니다(예: RETRIEVE_MIN_RATIO 기본 0.7에서 0.6, 하한 완화). 모호한 표현(완전한, 이전 상태 등) 대신 무엇이 같고 무엇이 다른지 적습니다.
  - 표에 새 행을 넣을 때 기준값이 정해지지 않았으면 비워 둔다고 적습니다. 요청에 없는 칸은 Gemini가 다른 행의 값을 본떠 지어내기 때문입니다.
  - 범위는 요청 문장이 아니라 파일:줄 범위로 지정합니다. 큰 재구성은 절 단위 줄 범위로 나눠 위임합니다.
- 기본 모델은 코드 파일과 문서 파일 모두 `gemini-3.8-flash-medium`이며 `AGY_MODEL`을 지정하면 모든 파일에 그 모델을 씁니다. 환경 변수는 `AGY_MODEL`, `AGY_WORK`, `AGY_RETRIES`(기본 2), `AGY_TIMEOUT`(기본 660초)입니다.
- `annotate.py` 실행은 백그라운드로 수행하고 완료 알림을 대기합니다.
- 결과 반영 후 Claude는 파일 내부 글을 직접 고치지 않습니다.
- 문제가 발생하면 사용자에게 보고하고 확인을 거쳐 요청(REQUEST)에 사실을 추가하여 다시 실행합니다.
- 사용자 보고에는 Gemini의 CHANGES 내용, 대조 결과, 의미 왜곡 의심 항목을 포함합니다. Gemini의 CHANGES에 적힌 변경 중 preserve가 되돌린 항목은 실제 파일에 반영되지 않으므로 보고 전에 백업 파일과 결과 파일을 대조합니다.

## 실행 명령

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/annotate.py FILE[:LOCATION][=REQUEST]...
```

- 파일 경로(`FILE`), 작업 위치(`LOCATION`), 요청(`REQUEST`) 형식으로 인자를 지정합니다.
- 작업 위치(`LOCATION`)는 줄 범위나 함수 이름으로 지정합니다. 생략하면 파일 전체를 대상으로 작업합니다.
- 요청(`REQUEST`)은 생략할 수 있습니다. 사용자 요청이나 코드에 없는 사실 정보만 기재합니다.
- 여러 파일에 글 작성이 필요한 경우 인자로 함께 묶어 한 번에 실행합니다.
- 백그라운드로 실행하고 완료 알림을 대기합니다.

## annotate.py 동작 과정

1. 프롬프트 생성
   - `assets/annotate-prompt.md` 자리표시자를 채워 프롬프트를 생성합니다. 프롬프트에는 절대 경로 대신 파일 이름만 넣고 도구 사용을 금지합니다.
   - 작업 위치(`LOCATION`)를 `12-15,20` 같은 줄 범위로 지정하면 프롬프트에 해당 줄을 줄 번호와 함께 보여 줍니다. 함수 이름이나 섹션 이름 범위는 강제하지 않고 프롬프트에만 전달합니다.
   - 프롬프트와 결과와 백업은 `AGY_WORK` 환경 변수에 지정된 작업 폴더에 저장하며 설정되어 있지 않으면 임시 폴더를 사용합니다.

2. agy 호출
   - 파일마다 agy를 병렬로 호출하여 비대화형으로 실행합니다.
   - 시간 초과나 agy 미설치는 해당 파일만 NG로 처리합니다.

3. 결과 형태 검사
   - 반환된 결과의 형태를 검사합니다. 원본 내용이 두 번 출력된 결과는 반영하지 않습니다.
   - 형태 검사에 실패하면 반영하지 않고 `AGY_RETRIES` 횟수만큼 다시 호출합니다.

4. 반영
   - 형태 검사를 통과한 결과를 대상 파일에 그대로 반영합니다.
   - 작업 위치(`LOCATION`)를 줄 범위로 지정한 경우 범위 밖 변경을 원본으로 되돌리며 문서 파일에도 적용됩니다. 범위 바로 앞이나 뒤에 끼워 넣은 줄은 범위 안으로 봅니다. 결과 출력의 `outside reverted` 값은 되돌린 줄 수입니다.

5. 검증
   - 코드 파일 검증은 `verify_code.py`가 수행합니다. `.py`는 ast, tokens, layout을 비교하고 SLASH_EXT 파일은 `//`와 `/* */` 주석을 제외해 비교하며 그 밖의 파일은 `#` 주석 기준으로 비교합니다.
   - 문서 파일은 `verify.sh`로 변경 사항을 검증하고 보고만 수행합니다.
   - 검증에 실패하면 원본으로 복원하고 `AGY_RETRIES` 횟수만큼 다시 호출합니다.

6. 기존 글 유지
   - 코드 파일에만 적용하며 문서 파일은 기존 글 유지를 적용하지 않습니다.
   - `preserve.py`가 원본에 있던 규칙에 맞는 주석과 docstring 및 빈 줄 배치를 되돌린 뒤 다시 검증합니다. 같은 코드 파일을 다시 실행해도 결과가 바뀌지 않습니다.
   - 요청(`REQUEST`)이 있으면 docstring과 파일 머리 설명을 되돌리지 않고 코드 옆 주석과 빈 줄 배치만 유지합니다. 요청으로 전달한 사실이 설명 글에 반영되도록 하기 위해서입니다.
   - 결과 출력의 `kept` 값은 되돌린 항목 수입니다.

7. 결과 확인
   - 검증을 통과한 결과마다 `claims.py`가 확인 필요 문장을 `check:` 목록으로 붙입니다. 대상은 근거 없는 수치, 근거 없는 식별자, 판단 표현(향상, 절감, 엄격, 완화 등), 단정 표현(모두, 완전, 항상 등), 새 용어(문서 파일만)입니다.
   - Claude는 목록의 각 문장을 원본 코드나 자료와 대조하고 틀린 문장과 근거 없는 문장을 사용자에게 보고합니다.
   - 목록은 다시 생성하지 않는 표시이므로 실행 시간이 늘지 않습니다.

8. 원장 기록 및 종료
   - 검증에 성공하면 ledger에 변경 파일 글 부분의 해시를 기록합니다. 파일 잠금으로 병렬 기록 시 항목 유실을 막습니다.
   - 모든 대상 파일의 처리가 정상이면 종료 코드 0으로 종료합니다.

## 케이스별 수행 절차

### 케이스 A. 문서 작성 및 수정 요청

사용자가 문서 작성이나 수정을 요청한 경우에 적용합니다.

1. 실행 인자 구성
   - 대상 파일 경로를 지정합니다.
   - 작업 위치가 파일 전체이면 위치를 생략합니다. 특정 위치만 수정할 경우 줄 범위나 섹션 명칭을 지정합니다.
   - 요청(`REQUEST`) 값으로 사용자 요청 내용을 전달합니다.

2. 실행 및 대기
   - `annotate.py` 명령을 백그라운드로 실행하고 완료 알림을 대기합니다.

3. 보고 및 추가 라운드
   - 반영된 결과를 Claude가 직접 수정하지 않습니다.
   - CHANGES 내용, 대조 결과, 의미 왜곡 의심 변경을 사용자에게 보고합니다.
   - `check:` 목록의 각 문장을 원본 코드나 자료와 대조하고 틀린 문장과 근거 없는 문장을 사용자에게 보고합니다.
   - 추가 수정이 필요한 경우 사용자 확인을 거쳐 요청(`REQUEST`)에 사실을 더해 다시 실행합니다.

### 케이스 B. 파일 내부 글 작성

코드 작성이나 수정 중 주석, docstring, 한글 문자열(LLM 프롬프트, 로그, 안내 문구) 작성이 필요한 경우에 적용합니다. 커밋이 차단되면 Claude는 안내된 `파일:줄 범위`를 그대로 `annotate.py` 인자로 넘겨 그 범위만 위임하고 파일 전체를 위임하지 않으며 `git add`로 다시 stage한 뒤 커밋합니다.

1. 실행 인자 구성
   - 대상 파일 경로를 정리합니다.
   - 작업 위치(줄 범위 또는 함수 이름)를 지정하거나 생략하여 파일 전체를 지정합니다. 커밋이 차단된 경우에는 안내된 `파일:줄 범위`를 그대로 지정하여 해당 범위만 위임합니다.
   - 코드에 드러나지 않는 결정 이유 등 사실 정보를 요청(`REQUEST`)에 기재합니다.

2. 일괄 실행 및 대기
   - 변경 대상 파일을 모두 인자로 묶어 백그라운드로 실행합니다.
   - 실행 완료 알림을 대기합니다.

3. 대조 결과 확인 및 보고
   - `verify_code.py` 대조 결과를 확인합니다. 코드가 변경되어 원본 복원된 파일이 있는지 점검합니다.
   - CHANGES 항목, 대조 결과, 의미 왜곡 의심 항목을 사용자에게 보고합니다.
   - `check:` 목록의 각 문장을 원본 코드나 자료와 대조하고 틀린 문장과 근거 없는 문장을 사용자에게 보고합니다.
   - 수정이 필요한 경우 사용자 확인을 거쳐 요청(`REQUEST`)에 사실을 추가하여 다시 실행합니다.
   - 커밋 차단으로 작업을 수행한 경우에는 `git add`로 다시 stage한 뒤 커밋합니다.

## 훅

- 안내 문구 주입: `UserPromptSubmit` 훅이 대화 시 안내 문구를 주입합니다.
- 커밋 차단 게이트: `PreToolUse(Bash)` 훅(`commit_gate.py`)이 커밋 명령 실행 시 동작합니다. 이번 커밋에 들어갈 내용만 검사합니다. 기본은 stage된 내용이고 `-a` 옵션이면 추적 중인 수정 파일 전체이며 경로를 지정하면 해당 경로만 검사합니다. 병합, 체리픽, 되돌리기, 리베이스 중에는 상대편 내용과 같은 글을 팀원이 이미 쓴 글로 보고 제외합니다. ledger 기록과 다른 글이 있으면 커밋을 차단합니다. 차단 메시지는 `파일:줄 범위` 형식으로 내가 새로 쓴 줄만 안내합니다.
- 사용자 직접 작성 승인: 사용자가 직접 작성한 글이 차단된 경우 사용자 확인을 거쳐 `python3 ${CLAUDE_SKILL_DIR}/scripts/ledger.py accept <파일>` 명령을 실행합니다.
- 차단 제외 대상:
  - 메모리 폴더
  - `/tmp/claude-*`
  - `settings.json`
  - 데이터 파일 확장자(`csv`, `json` 등)
  - `.git/info/agy-write-ignore` 파일에 적은 경로(git이 커밋하지 않는 개인 설정이며 worktree에서도 원래 저장소의 목록을 쓰고 파일이 없는 저장소는 제외 없이 검사하며 `/`로 끝나는 항목은 폴더이고 나머지는 파일 이름 패턴임)
